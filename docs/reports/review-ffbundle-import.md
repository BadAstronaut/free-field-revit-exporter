## IMPORTANT

I1. Sheet-name collision silently merges two sheets. importBundle.ts:226-231, 424-438. `sheetPdfName` replaces illegal chars with `_` and trims only. Two sheets whose number/name collide after sanitising ("A/1" vs "A_1", or duplicate numbers) map to the same (building, name): the second becomes version 2 of the first PDF file, the first sheet's drawing is no longer latest, and calibrations upsert on (pdfFileId, storey) so sheet 2 overwrites sheet 1's. Both outcomes report "imported". Fix: detect duplicate names across manifest.sheets before importing (append `(2)` or the sheet id suffix, or mark the later one skipped with a reason); also strip control chars / trailing dots, cap length, handle empty number (name becomes " - X.pdf" which sheetNumberOfPdfName reads as "").

I2. Weak dedupe fingerprint causes false "unchanged". importBundle.ts:418-433 + pdfImport.ts:40 hash = SHA-256(first 64 KiB + size). A re-exported sheet with the same byte length whose change lies after 64 KiB (edited schedule value or payload attachment, "120"->"121") is treated as unchanged: stale drawing, embedded freefield-sheet.json and calibration are kept while the report says unchanged. Fix: for bundle sheets use a full-content hash (SubtleCrypto over the whole buffer; cost is trivial vs the PDF parse), or compare size+full hash before skipping. (Same weakness already exists for IFC dedupe in ingestIfc, pre-existing.)

I3. Wrong-model fallback for calibration storeys. importBundle.ts:461-465. `vp.modelId` that points at a FAILED model (not in versionByModelId) falls back to `[...versionByModelId.values()][0]`, i.e. some other model; a same-named storey ("Level 1") in that model is matched and a calibration is written for a viewport of a different model (the b is shared, but the plan then maps to the wrong model's storey). Fix: only fall back when `vp.modelId` is null/undefined; if it is set and missing, warn and skip.

I4. Mirrored page still calibrated. bundleCalibration.ts:75, importBundle.ts:474-475. `affineWarnings` reports "mirrored (determinant <= 0)" but the calibration is still created at confidence 1; a two-point similarity forced proper from a mirrored affine puts the 2 control points right and everything else mirrored. Fix: treat det<=0 (and non-uniform scale beyond tolerance) as CalibrationInputError (skip + warning), or lower confidence.

I5. CSV formula injection. tableExport.ts:204-207 `csvCell` quotes only for , " CR LF. Cells from IFC/Revit parameter text starting with `=`, `+`, `-`, `@` (also tab/CR) execute as formulas when the CSV is opened in Excel. (toCell turns plain numbers like "-5" into numbers, which is fine; text like "-1+cmd" is not.) XLSX is safe: all strings are shared-string cells, never formulas. Fix: prefix `'` (or a tab) to text cells matching /^[=+\-@\t\r]/ that are not numbers, in CSV only.

I6. Link resolution by sheet number is ambiguous / breaks on " - ". sheetLinks.ts:105-118. `sheetNumberOfPdfName` cuts at the FIRST " - ", so a sheet number containing " - " ("A - 101" -> file "A - 101 - Plan.pdf" -> parsed "a") never matches target "A - 101". `find` returns the first PDF of the building with that prefix, including non-bundle PDFs, and compares case-insensitively ("a1" vs "A1" collide). Fix: resolve via a stored mapping (manifest sheet id/number -> pdfFileId), or match `startsWith(number + " - ")` / `=== number + ".pdf"` against the exact sanitised number, and prefer exact-case match.

I7. Base shift read after a possible silent partial import. importBundle.ts:359-375. If the bundle's IFC fails but the building already has another IFC, `base` comes from that old model; calibrations are skipped only because versionByModelId is empty (storey lookup fails). That works today but only by accident of I3's fallback; a pre-existing model that fails to match plus a successful second bundle model would be calibrated against the old base (correct by the shared-b rule). Acceptable; but add an explicit guard: if every bundle model failed, skip the calibration phase with one clear warning. Also persist b (spec/integration doc 9 recommends building.metadata) so later base-file changes are flagged: calibrations drift silently (known, in .last-task.md).

## NIT / minor

N1. Memory. parseBundle.ts:670 reads the whole zip into one ArrayBuffer, then per entry JSZip inflates (Uint8Array), `new File([bytes])` copies it, and ingestIfc/parsePdfFile read it again: ~3x per large IFC at once. For PDFs importBundle.ts:418-423 copies the whole PDF (`buffer.slice`) only to hash the first 64 KiB, then again for the File. Fix: hash from a subarray (or full-hash per I2) without slice; release `bytes` refs before ingest; no size cap on entries (zip-bomb: manifest.json is inflated unbounded before validation) - add a max uncompressed size check via JSZip `_data.uncompressedSize` or stream limit and max models/sheets counts in zod.
N2. parseBundle.ts:636-638 `normalise` only strips one leading "./" and does not resolve "..". Safe today (entries are only looked up in a Map, nothing is written to disk, IFC name uses `basename`) but a manifest `file` of "models/../models/a.ifc" reports "missing". Optionally reject `..` segments in manifest paths explicitly. Duplicate entries after normalisation silently overwrite (last wins).
N3. Schema gate is an exact literal `freefield.bundle/1` (parseBundle.ts:556,652). Any /1.x or /2 is rejected with a clear message; fine, but consider accepting `/1.*` minor versions (passthrough already tolerates extras).
N4. importBundle is not cancellable from the UI (BundleImportButton.tsx:92 passes no signal) and there is no rollback on abort/throw: models/sheets already written remain. setState after unmount is possible. TOCTOU between findPdfFileByName/hash check (importBundle.ts:424) and the tx in importPdfFile is harmless single-user.
N5. Calibration upsert and `setExtracted` are separate writes (importBundle.ts:476-502); a failure between them leaves a calibration with the level not marked extracted (re-import repairs). Could share one transaction.
N6. LinkView `getBaseCoordinates?.()` is read inside an async callback (LinkviewApp.tsx:249); before a model loads it returns null and the shift silently becomes 0, giving a floor plane at the unshifted height. Guard: if null, defer/retry or skip overlay until the base is known. LinkView resolves floors with `currentVersionId`, importer with latest version; equal in normal flows.
N7. useSheetPayload.ts:62-66 caches `null` when `getAttachments()` throws (readSheetPayload swallows), so a transient pdf.js failure hides the drawing data until reload. Cache only definitive results (no attachment) and not errors. Cache is keyed by pdfVersionId, which is correct (immutable per version); the old doc is not read across versions because PdfOverlay's cleanup nulls docRef before the new effect runs (verified). The payload's own sheetNumber is not cross-checked against the PDF name.
N8. sheetPayload.ts:128-135 `elementRecords[gid]`/`params[k]` on plain objects: a key "__proto__" sets the prototype instead of an own property (JSON.parse creates own "__proto__"). Local-object only, harmless; use Object.create(null) or Map. No size limit on the attachment.
N9. tableExport.ts:162 silently caps parameter columns at 60 (CSV/XLSX lose data without notice); xlsx.ts has no guard for Excel limits (1,048,576 rows, 16,384 cols, 32,767 chars/cell, `count` attr in sst is unique count not reference count - Excel tolerates). XML escaping, illegal-char stripping, CRC-32, header offsets and sheet-name sanitising are correct (checked field offsets against the ZIP spec; no zip64, fine below 4 GB / 65k entries).
N10. hitTest.ts: smallest-area-wins is right; a degenerate (zero-area) outline that contains the point would always win (area 0). Skip outlines with area 0 in asOutline.
N11. PdfOverlay.tsx fix is sound under StrictMode: per-effect `cancelled`, destroy of the owned `pdfViewer`, refs cleared only if still owned. The shared `disposedRef` is now vestigial (still set at lines 278/338). Cleanup does not destroy the pdf.js `api` doc of the viewer if the viewer does not own it (pre-existing).
N12. SheetDataLayer.tsx:123-127 link navigation resolves async and navigates even if the user has since changed sheet; guard with the version captured at tap time.
